## vendor/ 目录分析（iBuddy / DSH Desktop）

- `vendor/` 是 vendored npm 依赖仓库：`.tgz` 直接入库，`package.json` 用 `file:` 引用，`manifest.json` / `provenance.json` 记 sha256 + 上游 commit。
- 实测：2875 个 git 跟踪文件，200MB。被 `package.json` / `yarn.lock` 引用的只有 **345 个 tgz / 24.7MB（12%）**，剩下 2519 个 / 167.5MB 全是死重量。
  - 8 个旧 `vendor/dsh-runtime/<ver>` 目录 = 150MB（0.1.5-rc.2 … 0.2.1-alpha.2），只有 `0.2.1-rc.3` 在用。
  - 30 个旧 AA tarball = 17.5MB，`provenance.json` 的 `artifact` 只指向 1 个。
- `scripts/sync-vendored-runtime.mjs` 的 `checkVendor()` 只校验当前通道目录，不扫兄弟版本目录 → 删旧的不会 fail。
- 泄漏源：`prepare-agents-anywhere-release.mjs` 每次发版只增不删（第 219 行），`sync-vendored-runtime.mjs --write` 升级时只建新目录不删老的。
- 结论：可以清，但删工作树不减小 `.git`（历史 blob 还在），要瘦身得 `filter-repo` 重写历史。
- 未执行清理（用户未确认）。

## 本机启动 DSH Desktop 的完整流程（已验证跑通）

前置：Node v22.22.2 + corepack 0.34.6；`yarn` 不在 PATH，必须用 `corepack yarn`。

1. `git submodule update --init --recursive` → 162MB，pin 在 `1f81c047`
2. `YARN_NPM_REGISTRY_SERVER=https://registry.npmmirror.com corepack yarn install --immutable`
   → 1378 包 / 1.4GiB / 4 分钟。**不要改 .yarnrc.yml**
3. Electron 二进制缺失（`.yarnrc.yml` 有 `enableScripts: false`，postinstall 不跑）：
   `cd dsh-plugin-desktop/node_modules/electron && ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ node install.js`
   → electron 44.7.0，368MB，内置 Node 24.21.0
4. `corepack yarn workspace dsh-community-market build && corepack yarn workspace dsh-plugin-desktop build`
5. `corepack yarn run prepare:electron-native` → Windows 直接跳过（"fs-ext Electron binding is not required on Windows"）
6. `corepack yarn run prepare:runtime` → 下 Node 24.21.0 + Python 3.12.14（python-build-standalone, release 20260901），约 4 分钟，末尾跑 smoke
7. `cd dsh-plugin-desktop && env -u ELECTRON_RUN_AS_NODE node lib/bin.js`

### 关键坑：ELECTRON_RUN_AS_NODE=1

本机 shell 环境里被设了 `ELECTRON_RUN_AS_NODE=1`（宿主 WorkBuddy 是 Electron 应用，透传给子进程）。
后果：`electron.exe` 被当成纯 Node 跑，报
`SyntaxError: The requested module 'electron' does not provide an export named 'BrowserWindow'`。
**启动前必须 `env -u ELECTRON_RUN_AS_NODE`**，跟仓库无关。

### 跳过 root `yarn dev` 的原因

root `dev` 前缀是 `yarn market:prepare && yarn aa:prepare-release`：
- `market:prepare` 打 `registry.npmjs.org/dshmarket/latest`
- `aa:prepare-release` 必须拉 GitHub `main` 现构建（`DSH_AA_SOURCE_REF=pinned` 已不支持）

本地开发不需要刷新这两个 pin，直接跑 workspace 命令即可（用的就是 vendor 里提交好的 pin）。

## CI 改成手动触发

`.github/workflows/ci.yml` 的 `on:` 原来是 `pull_request` + `push`(master) + `workflow_dispatch`，
已删掉前两个，只留 `workflow_dispatch`。原因：fork 仓库、单人开发，push 不该触发 6 个 job（含 macOS universal DMG 9-17 分钟）。

副作用（都是无害的）：
- `changes` job 里 `BASE_SHA` 为空 → 直接判 `product=true`，永远跑全量
- `scripts/classify-ci-changes.mjs` 变成死代码（dispatch 路径不会调用它）
- `check` job 里 "Narrow Beta check on pull requests" 那段 `if: github.event_name == 'pull_request'` 永不执行（可删）
- `desktop-macos` 的 `DSH_MAC_SMOKE_ARCH` 永远走 `universal`

结论备忘：这套 CI 只构建不发布——`permissions: contents: read`，全文件无 upload-artifact / gh release / npm publish，
打包产物构建完直接丢。唯一的发布口子是手动在 `dsh-plugin-desktop/` 里 `npm publish`（该包没有 `"private": true`，beta/next 有）。

前置：fork 的 Actions 默认禁用，需在 Actions 页点「I understand my workflows, go ahead and enable them」。

## CI 加 Release 发布（手动、按需）

`workflow_dispatch` 新增输入 `release_tag`（默认空）。三个打包 job 各加 `actions/upload-artifact@v7`
（名称 desktop-windows / desktop-linux / desktop-macos，保留 7 天，`if-no-files-found: error`）。
新增 `release` job：`needs` 三个打包 job，`if: inputs.release_tag != ''`，job 级 `permissions: contents: write`
（其余 job 仍是只读）。用 `gh release create/edit + gh release upload` 挂产物，已存在则只追加。

产物路径（electron-builder `directories.output: dist`，相对 beta 包根）：
- `dsh-plugin-desktop-beta/dist/*.exe`（NSIS）、`dist/*.zip`（portable）
- `dsh-plugin-desktop-beta/dist/*.AppImage`、`*.deb`
- `dsh-plugin-desktop-beta/dist/mac-smoke/*.dmg`（smoke 非签名版；签名版在 `dist/mac-release`，CI 不产出）

action 版本（2026-10 实测 API）：`upload-artifact` 最新 v7，`download-artifact` 最新 v8。
注意：产物全部未签名 —— Windows 触发 SmartScreen，macOS DMG 未公证需手动绕过 Gatekeeper。
